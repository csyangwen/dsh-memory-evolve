# 记忆与审查规则（功能说明）

本文档说明 dsh-memory-evolve 的**行为与规则**——记忆系统如何分层、后台审查如何触发与产出、哪些内容会进入记忆/技能、需要用户确认什么。不含实现细节；若你想了解内部机制，直接看代码或 README 的配置表。

---

## 1. 记忆系统：四层轨道

插件维护四层互不污染的记忆，各层的"写入方式"与"注入方式"不同：

| 轨道 | 存什么 | 谁能写入 | 是否注入会话 |
|---|---|---|---|
| **用户档案 `user`** | 用户是谁、偏好、沟通方式、工作习惯 | 只有用户**确认后**才能写入（建议确认制） | ✅ 每个会话注入 |
| **全局事实 `memory`** | 环境事实、工具要点、技术惯例 | 只有用户**确认后**才能写入 | ✅ 每个会话注入 |
| **项目记忆 `project`** | 当前项目的约定、进展、关键决策 | 后台审查**自动沉淀**（无需确认） | ❌ 不注入，按需读取 |
| **今日日志 `daily`** | 今天做了什么、重要进展 | 后台审查**自动沉淀** | ❌ 不注入，按需读取 |

### 1.1 写入方式

- **user / memory（全局轨）**：模型和审查子代理都**不能直接写**。只能通过"建议"进入待确认队列，由你在设置面板（或 `/memory_review` 命令）逐条确认后才真正写入。这是为了防止无人把关的自我修改——全局轨内容每个会话都注入，写错影响最大。
- **project / daily（隔离轨）**：后台审查发现值得记录的内容时**直接写入**，无需确认。它们不注入会话，即使内容质量一般也只是占用文件空间，风险低。
- 你也可以直接对 agent 说"记住 XXX"，agent 会按目标轨规则写入。

### 1.2 注入与缓存

- **只注入低频变化的轨道**：user / memory（内容需确认才会变）以及可选的只读 Hermes 记忆。快照末尾有一行固定提示，告知模型"项目记忆与今日日志可随时用 memory 工具读取"，但**内容不注入**。
- 原因：DSH 的上下文快照是追加式的，注入内容一变就会追加新快照、降低 LLM 前缀缓存命中率。project/daily 每次审查都会变，注入会每轮破坏缓存，所以它们按需读取。
- 已知局限：即使只有全局轨，**任何确认写入**（或直接 `memory add`）仍会触发一次快照更新，前缀缓存相应截断。写入越频繁，缓存收益越小。这是 DSH 核心机制的固有行为。

### 1.3 记忆条目格式

- 每条记忆带时间前缀：全局轨 `[YYYY-MM-DD]`、项目轨 `[YYYY-MM-DD HH:MM]`、今日日志 `[HH:MM]`（文件名已含日期）。
- 项目记忆按**工作目录**隔离：每个目录一个独立文件，A 项目会话看不到 B 项目的记忆（也不注入，只能按需读取自己目录的那份）。

### 1.4 让模型主动读取项目/今日记忆

快照中的「按需记忆」提示行**已内建触发条件**：明确告诉模型"任务涉及项目上下文/对项目情况不确定 → 先读 target=project；用户问今天做了什么/需要当天信息 → 读 target=daily；不要凭猜测回答"。所以**不需要**额外写使用指引，插件默认就能让模型主动读取按需记忆。

可选补充：若希望模型额外知道"已安装该插件"或加个性化说明，可在全局记忆（MEMORY.md）放一条简短说明（非必需）。

## 2. 后台审查

### 2.1 触发时机

| 触发方式 | 说明 |
|---|---|
| **回合间隔** | 每 `reviewInterval` 个用户回合（默认 5）自动审查一次。只有用户消息触发的回合计数，重试/系统注入不计 |
| **终局补审** | 会话关闭时，未达到间隔但有过用户回合的会话自动补一次审查（短会话也有沉淀机会） |
| **手动触发** | `/memory_now` 随时对当前会话触发一次 |

### 2.2 审查看什么（转录）

- 审查子代理看到的是一份**增量转录**：只包含**上次审查以来**的新对话（进程重启后水位线仍保留，不会从头重看）。
- 转录只含**对话本身**：用户输入与助手文本回复，带轮次标记。工具调用、工具结果、模型思考、系统注入内容（运行时上下文/技能目录/AGENTS.md）一律不进入转录。
- 长消息截断时保留**开头和结尾**（编程任务的关键信息常在结尾），中间省略处标注省略字符数。
- 转录顶部附【会话信息】：会话 ID、工作目录、覆盖范围。摘要信息不足时，审查子代理可以**按需深读**完整会话（需配合 dsh-session-search 插件，未安装时摘要式审查不受影响）。

### 2.3 审查子代理的权限

审查在受限子代理中进行，它只能使用：
- `memory` 工具（写 project/daily；写全局轨会被拒绝）、
- `memory_suggest` 工具（提交全局轨建议）、
- `skill_manage` 工具（技能操作）、
- 已安装 dsh-session-search 时额外允许 `agent_session_read`（深读会话）。

它看不到你的其他工具，也无法访问原会话（只能读转录与深读接口）。

### 2.4 并发

同时最多一个审查在进行；审查异步执行，不阻塞你的会话；子代理会话本身永远不会触发审查（防递归）。

## 3. 审查产出规则（什么该记、什么不该记）

### 3.1 今日日志（宽松）

每个会话**至少写 1 条**：当天做了什么、任务产出、重要进展。只有纯寒暄（"你好"、"你是谁"）才允许不写。

### 3.2 项目记忆（宽松）

当前工作目录发生了**实质工作**（写文档/短文、改代码、调研、方案讨论、踩坑教训）→ 至少写 1 条（做了什么、关键决策/进展）。纯寒暄不记；无项目上下文跳过。

### 3.3 全局轨 user / memory（严格，宁缺毋滥）

只有以下内容才允许提建议（且进入队列后仍需你确认）：

- 用户透露的**稳定**个人信息、偏好、沟通/工作方式（需跨会话可复用；**单次出现的行为不算偏好**，需至少 2 次独立信号）；
- 非平凡、**稳定**的环境/技术事实。

**明确不建议的内容**：

- 与**已有记忆重复**的内容（审查提示词里会附上当前 MEMORY.md/USER.md 全文供对照）；
- **可复用的操作方法**——这类知识应进入**技能**，而不是全局记忆；
- 转录中对代码/配置**现状的描述**——代码演进快，描述容易过时（未来会话拿到的是过时"事实"）；
- 一次性任务叙事、瞬时错误、对工具的负面断言、密钥等敏感信息、重试即好的临时状态。

同一偏好多轮出现时**合并为一条建议**，不拆分。

### 3.4 技能（严格创建 + 用户确认）

技能会注入**每个会话**的系统提示词（技能目录全量注入），每多一个技能都会增加上下文并影响缓存，因此：

- **创建门槛**：只有同时满足 ① 多次尝试仍难解决（反复踩坑）② 难度大、非显而易见 ③ 后续可能多次复用，才允许创建技能。**一次性任务、简单任务不创建**；想不出类级名称说明不该创建。
- **优化已有技能不受此限**：发现已有技能缺步骤或过时，随时可以改进（但需先读取过该技能）。
- **确认制**：默认情况下，审查创建的新技能先进**待确认队列**（`pending-skills`），不会注入任何会话；你在设置面板「待确认技能建议」中**采纳**后，技能才进入技能库生效（采纳 = 移动文件，立即实现），**拒绝**则删除。
- 技能命名必须是 kebab-case 的类级名称（如 `systematic-debugging`），禁止一次性任务名（如 `fix-pr-123`）。

## 4. 确认机制一览

| 内容 | 队列 | 确认方式 | 生效方式 |
|---|---|---|---|
| 全局记忆建议（user/memory） | `SUGGESTIONS.jsonl` | 设置面板逐条采纳/拒绝，或 `/memory_review` 命令 | 采纳后写入对应记忆文件，下个请求随快照注入 |
| 新技能（默认） | `pending-skills/` 目录 | 设置面板「待确认技能建议」采纳/拒绝 | 采纳 = 移动进技能库，立即被所有会话加载 |

一些辅助机制：

- **建议频次**：同一内容被多次建议时，队列中只保留一条并累计"已建议 N 次"（面板按频次排序、高频置顶）——反复出现的信号说明它很可能真的值得确认。
- **采纳前可编辑**：全局记忆建议在面板采纳前可以修改文本，修改后的内容才会写入。
- **自动沉淀开关**：`autoApproveGlobal`（全局记忆自动写入，不逐条确认）与 `skillReviewEnabled`（技能自动创建，不经确认）**默认都是关**，需要你显式开启——开启后审查产出直接生效，注意提示注入风险。

## 5. 会话页记忆 Tab（可选）

设置面板开启「会话页记忆 Tab」后（默认关），会话页顶部出现「记忆」标签页，可直接查看/编辑记忆文件：

- **查看**：全局规则、长期记忆、用户档案（只读预览）；项目记忆、今日日志（可编辑）；
- **编辑**：只有项目记忆与今日日志可编辑（保存即写文件）；全局轨与 AGENTS.md 只读（需通过确认制或直接编辑文件）；
- 每行都有"用系统工具打开"按钮。

## 6. 常见问题

**Q：为什么我确认了一条建议，会话里的记忆没立刻变？**
A：写入立即完成，但注入发生在下一个请求的上下文快照中；当前已渲染的快照不会回改。

**Q：项目记忆不注入，模型怎么会知道项目的事？**
A：快照中有固定提示行告知模型可随时用 `memory` 工具读取（target=project / daily）；它会在需要时主动读取。

**Q：技能创建为什么还要确认？**
A：技能注入所有会话且会长期存在，相当于修改"系统提示词"。默认进待确认队列，确保只有你认可的经验成为全局技能。

**Q：审查会看到我的敏感信息吗？**
A：审查转录只含对话文本（工具输出、思考不进入）；密钥、令牌等敏感内容也在"禁止沉淀"清单内。审查子代理只能使用白名单内的工具。
