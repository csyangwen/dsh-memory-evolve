# DSH UI 设置模块（dsh-ui-settings）调研报告

日期：2026-08-09
状态：调研完成，待开工
决策人：用户

## 1. 模块定位

Memory Evolve 插件新增独立子模块「DSH UI 设置」（dsh-ui-settings）：
- 对 DSH web 界面做样式级修改、加样式相关小功能
- 后期扩展方向：主题更换等
- **第一个功能**：左侧会话列表筛选——默认只显示"进行中"的会话，可切换回"显示全部"

## 2. 需求语义（用户拍板 2026-08-09）

筛选默认隐藏**纯 idle 的会话**（从未在跑/没有待处理事项）；以下类型**全部保留**：
- running（正在生成）
- 等审批 / 等回答 / 待 plan-review（pendingInteraction）
- 有子代理在跑（runningSubagentCount > 0）
- 出错
- completed（已完成未查看，绿色 done 点）

即：**只隐藏没有任何状态点的会话行**。

## 3. 可行性结论

**能实现，纯客户端 DOM 增强，不改 DSH 核心**。核心依据：

### 3.1 左侧列表架构

| 项 | 事实 |
|---|---|
| 渲染组件 | `ui-workspace` 包的 `WorkspaceBrowser`（`packages/client/ui-workspace/src/client/WorkspaceBrowser.tsx`） |
| 槽位 | `sidebar.workspaces`，**`kind: 'single'`**（ui-sidebar `SidebarRoot.tsx` 声明）→ 插件不能叠加注册组件，只能 DOM 增强 |
| 树结构 | `role="tree"` 容器 → groupSection → 工作区行 / 会话行 |
| 三种行 | 工作区行：`div[role=treeitem][aria-expanded]`；会话行：`div[role=treeitem][aria-selected]`；搜索行：`button[role=treeitem][aria-selected]` |

### 3.2 状态标记锚点（关键发现）

`StateDot`（`ui-primitives/src/StateDot.tsx`）渲染稳定属性 **`data-state`**：
- `ongoing`：running（svg 像素追逐动画）
- `warning`：等审批 / 等回答 / plan-review
- `error`：出错
- `done`：completed（已完成未查看）
- **纯 idle 行不渲染任何状态点**（Rows.tsx 源码：`primaryStatus.state !== 'done' || row.completed` 为 false 时不渲染）
- 有子代理在跑：即使自己 idle，也渲染 ongoing 点

### 3.3 筛选规则（纯 CSS 可实现）

```css
/* 开启筛选时：隐藏没有任何状态点的会话行（= 纯 idle） */
.filter-on div[role="treeitem"][aria-selected]:not(:has([data-state])) { display: none }
```

- `:has()` 需要 Chrome 105+（2022-08 起），现代浏览器无问题
- React 重渲染后选择器自动生效，**无需 JS 轮询状态**
- 搜索行是 `<button>`，天然豁免（搜索时不受筛选干扰）
- 工作区行有 `aria-expanded` 无 `aria-selected`，天然豁免

## 4. 实现方案

### 4.1 模块装配（遵循项目惯例）

- 独立子模块，**独立开关 `uiSettingsEnabled`（默认开**——用户明确要的功能）
- 独立客户端入口 + 独立 CSS 文件（`ui-settings-styles.css`）
- 不借其他模块开关（教训：广播曾挂 COI 下导致联动事故）

### 4.2 客户端逻辑（src/client/ui-settings/）

1. **CSS 注入**：apply 时挂 `<style>`，样式 token 用 `--dsw-alias-*`/`--dsw-static-*`，集中定义变量预留主题扩展
2. **切换按钮注入**：
   - 锚点：`[role="tree"]` 容器（或侧边栏 regionArea）
   - 在列表区域插入小工具条/按钮（默认开启态）
   - **MutationObserver 保活**（技能经验：React 重渲染会清掉注入 DOM；`childList+subtree`，先匹配目标特征再标记 injected）
3. **偏好持久化**：localStorage（第一版不建宿主端 API；后期做主题时再考虑 /dsh-ui-settings API）
4. **rail（收起）状态**：无树渲染，筛选逻辑自然不生效，无需处理

### 4.3 预留扩展

- CSS 变量集中管理（`--dsh-ui-*`），后期主题更换可直接覆盖
- 模块目录独立（src/client/ui-settings/ + lib 端无必需改动，装配开关即可）

## 5. 风险点

1. **CSS Modules hash class 不可依赖**——一律用 ARIA 属性锚定（`role`/`aria-selected`/`data-state`），稳定
2. 若上游未来改变会话行结构（如 idle 行也渲染 done 点），选择器需同步调整——代码注释 + 项目记忆记录
3. 注入按钮被 React 重渲染清掉是常态，MutationObserver 保活是必须
4. 宿主端改代码需重启 dsh web；客户端 rebuilt 即可（构建流程见 build.mjs）

## 6. 验证计划（开工时执行）

1. esbuild 构建 client bundle（PLUGIN_ID 从 package.json 动态读）
2. `ctx.clientModuleHost.rebuilt('dsh-memory-evolve')` + 浏览器刷新

## 追加：功能五「上下文占用提醒」（2026-08-09 用户需求）

### 需求
输入框右下侧的上下文使用量**圆环**（ContextMeter）在占用率 ≥30% 时变**黄色**提醒、≥40% 变**红色**提醒；低于阈值恢复原色。

### 调研结论（可实现，纯客户端 DOM 增强）
- 实现文件：`ui-conversation/src/client/skeleton/ContextMeter.tsx`——SVG 圆环（viewBox 14、半径 5.5、周长 34.56），进度环 circle 的 `strokeDasharray = "${34.56×percent/100} 34.56"`（**percent 可直接从 dasharray 反推**：percent = dash/34.56×100）；颜色由 hash class `.fill`（stroke: --dsw-alias-label-tertiary）控制——插件不能改 class，需 JS 设 inline stroke（优先级高于 class）
- 稳定锚点：`button[aria-haspopup="dialog"] svg circle[stroke-dasharray]`（trigger 的 aria-haspopup="dialog"；TodoPanel 的虚线圆环是固定 `2.4 2.4` 且不在 dialog 按钮内，天然排除）
- 颜色用 token：黄=`--dsw-alias-state-warn-primary`、红=`--dsw-alias-state-error-primary`（深浅主题自适应）
- 保活：percent 更新走 React 属性更新（stroke-dasharray）→ MutationObserver `attributes: true, attributeFilter:['stroke-dasharray']` + childList 保活（元素重建后重应用）
- 开关：新功能「上下文占用提醒」（默认关，与其他功能一致，放「综合」子 tab）
