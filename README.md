# dsh-memory-evolve 使用场景指南

> **一句话**：让 DSH 里的 AI 拥有跨会话的长期记忆、帮你管理待办与技能、还能拉起一群 AI 会话和外部 AI 代理协同干活——**越用越懂你，换会话不丢上下文**。
>
> 本指南按真实工作流组织，每个场景讲「适合谁、能做什么、怎么用、会得到什么」。
>
> 相关文档：[详细功能说明](README-详细说明.md) · [记忆同步](docs/记忆同步.md) · [更新日志](docs/CHANGELOG.md)

---

## 认识它（30 秒）

装上插件后，打开任意会话，你会多出一排能力标签：**记忆 · 技能 · 待办 · COI 调度 · 会话广播 · 提示词 · 临时信息 · 记忆同步 · 模型设置 · 书签 · 会话评审 · Web UI 设置 · Memory Evolve 设置**。AI 侧则多了一批工具：记忆读写、待办、技能管理、本地文件搜索、会话编排、会话广播、外部 AI 派单、提示词注入、模型查询……

一句话概括这些能力：**让 AI 记住你、替你管、替你做、互相配合做。**

> 小提示：插件里很多能力默认关闭（不占 AI 的工具清单），需要时在「Memory Evolve 设置」里打开即可。下面的场景大多是组合玩法——**把相关功能都打开，才能串成完整的流水线**。

## 场景一：让 AI 真正记住你（长期记忆）

**适合谁**：所有人。这是插件的核心，也是其他一切功能的地基。

AI 的对话是「一次性」的：换项目、隔几天、开新会话，它就忘了你是谁。插件的五轨记忆让 AI 拥有**跨会话的长期工作记忆**：

- **用户档案**：你的偏好、公司、沟通习惯——AI 每回合都能看到；
- **全局事实**：环境、工具、惯例等长期知识；
- **项目关键记忆**：当前项目的约定、决策、架构、踩坑，自动注入上下文，重要结论可标记**只在某个 git 分支生效**；
- **项目日志 / 每日日志**：每回合自动记录进展，按需读取，历史可追溯。

**怎么用**：

1. 正常和 AI 对话即可——每回合结束时它会自动把进展写进项目日志和今日日志；
2. 发现重要事实时对它说「**记一下：这个项目的部署端口是 8080**」，它会写入项目关键记忆，**你确认后**才生效——AI 不会擅自往记忆里写东西；
3. 过几天、换了个会话，直接问「**查一下记忆，上次我们定下的架构决策是什么**」——它能无缝衔接；
4. 记忆多了之后，让 AI「**把 XX 那条记忆归档**」——归档条目不再注入上下文，随时可转回；
5. **情绪反馈记录**：你对工作结果的评价（如「太好了」「怎么还没改对」）会被 AI 记入当日与项目日志（`【反馈】` 行，含情绪、任务分类、你的原话）——积累后随时可以让 AI「**分析一下最近我对哪些方面不满意**」，判断它在哪类任务上做得好/不好。

**会得到什么**：AI 从一个「每次会话都失忆」的对话机器，变成了解你全盘工作的长期伙伴——隔天继续开发，它直接引用昨天的结论，不用你复述。

## 场景：多台电脑共享项目记忆（记忆同步）

**适合谁**：办公室和家里两台电脑干活、或有同事协作同一个项目的人——不想在每台电脑上把重要结论重新讲一遍。

**怎么用**（详见 [记忆同步](docs/记忆同步.md)）：

1. 「Memory Evolve 设置 → 配置」打开「**记忆同步**」模块开关（这只是让功能可见）；
2. 在项目会话的「**记忆同步**」Tab 打开「**本项目同步**」——点「开始同步」即可（记忆远端默认用你的代码仓库，自动存进专属分支，不污染代码），再点「同步并推送」完成首次推送；**代码公开（如 GitHub 开源）但记忆想私藏**？填一个**共享记忆仓库**地址——一个仓库装所有项目的记忆（每项目一条专属分支），记忆与代码彻底隔离；
3. 另一台电脑 clone 项目后打开——**自动认亲**（同一仓库地址 = 同一项目），拉下来即可继续用；
4. 平时照常写记忆（实时落盘、零延迟），攒一批点一次「同步」；两台电脑都改了同一条记忆才会出现冲突，Tab 里选「采用本机 / 采用远端 / 两者都要」即可。

**会得到什么**：项目关键记忆、项目日志、归档、项目待办跨设备一致；填了共享记忆仓库后，**全局记忆（用户档案/每日日志/待办）也能跨设备**（四个独立轨开关，开哪个同步哪个）——换电脑不换记忆。**没开同步的项目完全不受影响**（保持纯本地状态）。

## 场景二：多项目并行开发，每件事都不丢（待办 + 项目日志 + 本地搜索）

**适合谁**：同时维护多个项目、经常被「之前那个方案是怎么定的」卡住的开发者。

- **四轨待办**：生活 / 工作 / 项目 / 每日。「项目」轨按工作目录隔离，换目录互不干扰。说「**记住，周五前把二级面板部署到手机访问实例**」，自动落成项目待办（带重要/紧急、截止日期）；每天收尾 AI 会提醒你到期的待办；
- **项目日志**：每个项目的进展按目录隔离沉淀，日志自动带 `[git main]` 分支标记，可溯源；
- **本地文件搜索**：对 AI 说「**搜一下本机有没有写过类似的东西**」——按文件名找文档（可扩展到全类型）；也能内容检索：「**哪个文档里提过 XX**」直接返回命中文件和片段。

**怎么用**：

1. 新项目开工直接开聊，项目日志自动建档；
2. 冒出的想法对 AI 说「记住」，它会进待确认队列——到「待办」里**采纳或拒绝**，你说了算；
3. 想不起来就问「之前有个文档提到过 XX」。

**会得到什么**：同时开 3 个项目也不乱——每个项目的记忆、待办、文档线索各归各的目录，问一句就能捡起来。

## 场景三：一个人指挥一群 AI 干活（内部团队）

**适合谁**：想把 AI 用成「团队」的人——一个主会话指挥美工、前端、后端、测试多个子会话。

**怎么用**：

1. **拉起团队**：对主会话的 AI 说「**创建 4 个会话：美工负责网站视觉、前端负责页面、后端负责接口、测试负责验收，把它们拉进同一个协作房间**」——它立刻创建 4 个标准会话（出现在左侧列表、随时可接管），自动继承你的模型与工作目录；创建时可指定 **Agent 预设**（如「用代码模式创建前端会话」），决定该会话的工具面与人格；
2. **协作沟通**：房间建好后，**谁改了什么、谁干完了，全员可见**；成员状态（正在生成 / 空闲）自动出现在「房间动态」里；**房间消息可以带图片**——截图直接发群里，接收方 AI 通过 read 拿到图片文件路径，可读图、可转发到 IM 渠道；
3. **派活与催活**：问 AI「**现在谁在干活、谁空闲了**」，它会查看各会话状态；对空闲的会话说「**叫前端把结果发过来**」，AI 自动唤醒它并派活——不会批量自动唤醒，一切由你（或你的主会话）有意识地指挥；
4. **防冲突**：同一项目多个会话并行改代码时，开工前对 AI 说「**声明一下你要改哪些文件**」——其他人（及其 AI）能看到「谁在改什么」；真撞车了，写入方会收到冲突警告，还有「工作区活动」随时显示谁在跑、在干什么；
5. **结果回传**：各成员干完把结果发回房间，你汇总确认。

**持续运转（关键）**：主会话自己一直在运行，所以它能**随时唤醒已经休息（空闲）的会话继续干活**——催活、收结果、派下一轮，哪怕你不在电脑前，队伍也能一路推进到出结果。唯一的前提是**主会话所在的 DSH 进程保持运行**；如果主会话空闲了或 DSH 被关掉，唤醒链就停了——需要你回来发一条消息，队伍重新开动。

**会得到什么**：一个人的开发产出，变成一个小团队的吞吐。任务交接、唤醒、冲突预警全链路自动化，房间消息留痕可查。

## 场景四：重活派给外部 AI 代理（外部外援）

**适合谁**：需要把大任务（视觉重设计、代码审查、完整功能开发）交给专用 AI 代理（Kimi / Codex / Grok / Hermes）的用户——不想被阻塞，又不想错过结果。

**怎么用**：

1. 对 AI 说「**把这个任务派给 grok：移动端适配改造**」——后台异步执行，立即返回任务号，**不卡当前会话**，你可以继续聊别的；
2. 期间随时问「**任务进度如何**」，或在「COI 调度」里看实时日志流；
3. 派单时 AI 可自主选择带上你的项目记忆——外部代理也「懂项目约定」；
4. **派单可以带图**：对 AI 说「**把这张截图发给 grok 分析**」——附件支持本地路径/远程 URL/本会话图片（你在输入框贴的图），codex/kimi/hermes 都能真看图（grok 走 prompt 读图，zcode 纯文本会明确拒绝）；
5. 完成后结果摘要**自动写入项目日志与今日日志**——派出去的活自动变成你的记忆资产。

**会得到什么**：AI 派活给 AI，你只负责确认验收。视觉改版、深度代码审查、批量重构这类「重活」都能甩出去，主会话保持轻快。

## 场景五：内外协同——一支队伍，两种兵种

**适合谁**：任务大到单靠一边搞不定的人。这是插件协作能力的完全体：**内部会话负责「需要上下文和来回打磨的活」，外部代理负责「一次性重活」，两者通过记忆、房间、提示词串成一条流水线。**

一个完整的真实流程（产品视觉改版）：

1. **分工**：主会话 spawn 前端、测试两个内部会话并拉进房间；同时把「全站视觉重设计」派给外部代理 Kimi；
2. **外部主刀**：Kimi 后台跑重设计（不占任何会话）；期间内部前端会话先做数据层和页面结构，不干等；
3. **接力**：Kimi 完成，摘要自动沉淀进项目记忆——主会话把设计结论发到房间，前端会话**读记忆拿到设计规范**，开始集成；
4. **问题升级**：集成中发现一个诡异样式问题，前端会话卡住——主会话把这个 bug 派给 Grok 深挖，结论回房间，前端会话照结论修复；
5. **验收**：测试会话跑完验收流程，结果发回房间，你最后确认。

协作的四个结合点，可以自由组合：

- **任务接力**：外部代理的产出（摘要/结论）自动进记忆 → 内部会话接力执行——**外部做重活，内部做集成与打磨**；
- **问题升级**：内部会话遇到难啃的问题 → 主会话派给外部代理深挖 → 结论回房间——**内部快节奏迭代，外部慢工出细活**；
- **标准统一**：给外部代理派活时，注入你沉淀的提示词（如「代码审查清单」「PRD 规范」）——**外部代理按你的流程干活，不靠运气**；
- **状态同步**：谁在跑、谁干完了，房间 + 工作区活动 + 通知随时可见——**你不用当人肉调度员**。

**会得到什么**：一条「外部主刀 → 内部集成 → 测试验收 → 你确认」的完整流水线。大任务不再是一个人（或一个 AI）硬扛，而是内外两支队伍分工协作。

## 场景六：AI 的自我纪律——提示词注入

**适合谁**：想把「好用的工作方法」沉淀下来、让每个 AI（包括外部代理）都按同一套流程干活的人。

提示词库是**指令范式资产库**：代码审查、调试、PRD、测试策略……把常用的工作方法固化成提示词（可分类、可搜索、可启用/禁用）。

**怎么用**：

1. **AI 自己选、自己注入**：AI 觉得当前任务适用某套流程时，它会自己查看提示词库、选中合适的提示词注入自己——「接下来按代码审查清单执行」；下一轮它自动遵循，**不打断当前回复**；也能「立即注入」，当前回合马上生效；
2. **你一键注入**：在「提示词注入」里选中一条，点「注入一次 / 持续注入 / 立即注入」——持续注入就是「每回合提醒 AI 按此纪律干活」；
3. **临时注入**：不建提示词，直接输入一段要求注入，自动存入库中，下次复用；
4. **派活带纪律**：给子会话、外部代理派活时，让 AI 把对应提示词一起带上——**整个团队用同一套标准**。

**会得到什么**：好方法不再只存在你脑子里或一次对话里——它变成可复用的「团队操作手册」，AI 会主动遵守，你只管维护手册质量。

## 场景七：会话太长、太贵、容易糊——书签与分支

**适合谁**：对上下文开销敏感、一个会话动辄上百轮的深度用户。

- **会话书签**：每一轮都可以点星（☆）标记，「书签」列出全部书签（名称/轮次/时间/摘要，可搜索），**点击一键跳回任意一轮**——探索到「这个结论很重要」就打个星；
- **任意轮分支**：官方只支持从最后一轮创建分支；本插件把**中间任意轮的分支入口接管**——书签列表点「分支」（或直接点官方分支按钮，中间轮会弹出确认），走官方分支通道创建新会话，进入官方分支谱系；
- **上下文占用提醒**：输入框圆环实时显示上下文占用——≥30% 变黄、≥40% 变红，提醒你该打书签、该开分支、该开新会话了。

**怎么用**：

1. 探索性会话在关键轮次点 ☆，给书签起个名字（如「方案 A 评审结论」）；
2. 想从中间某个决策点另开一条线，书签列表点「分支」；
3. 看到圆环变红，把当前会话打个书签，开新会话继续。

**会得到什么**：上下文不再是一根只能从头滚到尾的绳子，而是**带锚点、可分支、可跳转的时间线**——每一轮的探索成果都能被精准复用，不会再因为「会话太长了」被迫放弃中间的好结论。

## 场景八：离开电脑也能用（手机访问 + 会话筛选 + 通知）

**适合谁**：离开电脑也想继续和 AI 协作、或者同时开很多会话看不过来的人。

- **手机浏览器访问**：DSH 界面适配了手机——对话区/消息气泡满宽、输入栏「⋯」上拉收纳工具栏与模型选择，手机上操作和电脑端一致；
- **会话列表筛选**：左侧列表可只显示「进行中的会话」，一屏看清谁在干活——桌面端同样适用；
- **渠道通知（de_notify）**：对 AI 说「任务完成用飞书通知我」，重要结果推到飞书/QQ/微信/企业微信，电脑前/手机上立刻知道（通知内容带「这是通知」标注，可附图片/文件）；
- **web 站内通知（de_notify channels=web）**：对 AI 说「发个站内通知给我」，通知直接落到**网页右上角的铃铛**——未读数字徽标 + 弹窗列表，能看到「哪个会话发来什么」，点主题跳转到那个会话、长内容点「查看详情」打开大弹窗看全文；铃铛可随意拖动、松手吸附到屏幕左/右边缘（位置记忆）。发到 web 和发到飞书等 IM 是同一句话，只是换个送达目的地（channels 传 `web`，或 `all` 一起发）；
- **渠道直发（de_channel_send）**：AI 随时主动把文本/图片/文件发到你的 IM 渠道（不带通知标注）——「把生成的图片/文档发给我」类场景；四个渠道（飞书/QQ/微信/企微）全部支持，附件来源可选本地路径/远程 URL/内联 base64/**本会话图片**（sessionImage=true 直接转发你在 DSH 输入框粘贴/拖入发送的图；attachmentId 显式引用，配合 de_session_images 先查本会话有哪些图，需 DSH 260810+ 快照）。

**会得到什么**：重活照派、进度照盯，人不用守在电脑前——回电脑后从左侧列表接管会话继续。

## 场景九：给每个会话配一个隐形评审员（会话评审）

**适合谁**：想让 AI 干活时有一双"第二眼睛"把关、又不想自己逐句盯的人——尤其是项目里定了纪律（如"回复前先说明自己在哪个目录"）却总发现 AI 聊着聊着就忘了的情况。

**能做什么**：

- **独立评审员**：给每个会话挂一个独立的评审会话，它**只观察你在界面上看到的对话**（用户说的话 + Agent 的回复正文），看不到思考过程、工具调用参数等内部细节——像旁边坐了一位只旁听对话、不碰键盘的同事；
- **每轮实时评审**：对话每推进一轮，评审员就基于**完整上下文**评审一次——它是持续会话，像普通 LLM 长对话一样记住全部历史、**永不截断**，不会"忘了前面说过什么"；
- **需要时实时提醒（steer）**：评审员发现值得说的点，会以**用户指令的形式**注入当前会话——Agent 会把它当成你说的话直接执行（2026-08-13 拍板：实测带"非用户指令"标记会让 Agent 质疑来源、执行力下降，所以伪装成用户指令效果最好）；GUI 对话流中这类消息显示为**折叠行 `[severity]` 前缀**，方便你一眼认出哪些话其实是评审员说的；
- **四级严重度**：`info`（仅记录、默认不注入主会话，可配置注入）/ `nit`（小建议）/ `concern`（值得处理）/ `blocker`（必须立即处理）——不是所有话都打断，只有该说的才说；
- **新建评审会话**：面板里一键清空评审员的上下文与记忆重来——新会话第一条指令由你告诉它背景，上下文长度由你掌控；
- **直接向评审员提问**：面板里随时提问，它立即回答（回答只在评审面板展示，不注入主会话流）——像随时可以问的旁听同事；
- **四层级约束**：系统提示词（全局默认，可查看全文/修改/一键恢复）/ **项目约束**（本工作区共享）/ **会话约束**（本会话保留）/ **本次评审会话约束**（随"新建评审会话"清空）——四层拼接注入，冲突时越局部越优先；
- **记录可查**：评审记录 JSONL 持久化，面板「记录」可追溯。

**怎么用**：

1. 「Memory Evolve 设置 → 配置」打开「**会话评审**」（`advisorEnabled`，默认关闭）；评审模型缺省继承当前会话模型，也可单独配置 `advisorProvider`/`advisorModel`；
2. 会话页出现「会话评审」悬浮窗，点开面板即可看到评审员的实时评审流与上下文占用；
3. 在「约束」Tab 给评审员立规矩（如项目约束："每次回复前先说明自己在哪个目录"），保存立即生效；
4. 想让评审员重头开始就点「**新建评审会话**」；想直接问它就点「**提问**」；
5. Agent 侧：评审提醒以折叠行 `[severity]` 出现在对话流里——你能看到评审员说了什么、Agent 是否照做。

**会得到什么**：每个 AI 会话都多了一位持续在岗的"旁听同事"——它不打断你的节奏，只在关键时刻以你的口吻提醒 Agent 纠偏；项目纪律、会话约束有人替你盯着，不会聊着聊着就忘了规矩。

## 还有这些能力（一句话索引）

- **技能自我进化**：反复踩坑的方法论自动固化成技能，同类任务下次直接按流程执行；
- **技能管理**：记忆 Tab 里浏览/搜索/禁用/编辑全部技能、添加自定义技能目录（原独立插件 dsh-skills-manager 已合并进本插件，旧插件用户升级前先按安装文档卸载旧插件）；
- **临时信息**：会话页一个持久化的 Markdown 便签，随手记、重启不丢；
- **会话搜索**：让 AI 搜索本机其他 AI 工具（如 Codex）的历史会话——「之前 Codex 里做过 XX」直接问；
- **模型配置**：插件侧维护各模型的启用状态、思考等级、备注，并标注**是否支持图片输入**（🖼 标记，AI 选模型时一目了然）；
- **回合内记忆审查**：每隔 N 轮，AI 主动提炼值得记住的信息交给你确认——记忆库自己会生长；
- **版本检测与更新**：多设备/多用户部署时，「Memory Evolve 设置」Tab 的「版本」页自动检测远端发布版本（git tag v0.x.y），检测到新版本时设置 Tab 出现 🔴 红点，由你决定是否更新（详见下方「发布版本」）；
- **会话评审（Advisor）**：给每个会话挂一个独立评审员——只观察界面可见对话（不含思考/工具调用），每轮实时评审、需要时以用户指令形式实时提醒（info/nit/concern/blocker 四级；info 默认仅记录），持续会话永不截断，支持新建评审会话/直接提问/四层级约束/记录可查。默认关闭，详见[场景九](#场景九给每个会话配一个隐形评审员会话评审)。
- **web 站内通知**：渠道通知（de_notify）新增 `web` 渠道——AI 发通知直接落到网页右上角铃铛（未读徽标 + 弹窗列表 + 点主题跳会话 + 长文大弹窗 + 拖拽吸附左右），与飞书等 IM 渠道同一套通知语义。默认关闭，随「通知模块」（`notifyEnabled`）开关启用，详见[场景八](#场景八离开电脑也能用手机访问--会话筛选--通知)。

## 发布版本

插件使用 **git tag（v0.x.y）** 作为发布版本标识：日常开发推送 main 分支不会触发任何更新提示，只有打了发布 tag 才会被各设备检测到。

**发版流程（开发者）**：

```bash
# 1. 发布前检查：工作树干净、构建通过、测试全绿
git status                 # 应为 clean
pnpm build                 # client bundle 构建通过
npm test                   # 全量测试通过

# 2. 确认 main 已与远端同步（tag 必须打在已推送的 main 提交上）
git push origin main

# 3. 打 annotated tag（附注即发布说明，会被各设备在更新时展示），并推送
git tag -a v0.2.0 -m "更新说明：……"
git push origin v0.2.0
```

**各设备更新（使用者）**：

- 进入 Web UI 后自动检测（24 小时内最多自动检测一次，也可点「检查更新」强制检测）；
- 检测到新版本时，设置 Tab 出现 🔴 红点；进入「版本」页点击「更新到 v0.x.y」；
- 更新完成后**必须重启 dsh web 再刷新浏览器**（仅刷新页面不会加载新代码）；
- 更新后插件处于 detached HEAD（跟随发布 tag）：继续用「版本」页的更新按钮升级即可，**不要直接 `git pull`**；
- 想回到开发轨：`git checkout main && git pull --ff-only`。

**更新安全机制**：只接受严格格式（v0.x.y）且位于 origin/main 历史的 tag；更新前校验本地工作树干净；更新过程有跨进程锁与失败回滚，不会把半更新状态留给你。

## 三条原则

1. **AI 只提议，你确认**：AI 自建的记忆、待办、技能都先进待确认队列——所有会真实改变 AI 行为的写入，决定权都在你；
2. **不重复造轮子**：官方已有的能力不碰，只做官方没做、且真实解决痛点的；
3. **内外有别、协作互补**：内部会话负责需要上下文的活，外部代理负责一次性重活，记忆、房间、提示词把它们串成一条流水线。
